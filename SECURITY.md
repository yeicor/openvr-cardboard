# Security policy

OpenVR Cardboard is a hobby project that talks to webcams, gamepads, a phone
on the local network and the SteamVR/OpenXR runtime on the same machine. This
page describes the supported versions, the intended trust boundaries and how to
report a problem.

## Supported versions

Only the latest tagged release and the current `main` branch receive fixes.
Older tags remain available for download but are not maintained.

## Reporting a vulnerability

Use GitHub's private vulnerability reporting on the repository's **Security**
tab (Security advisories). Please do not open a public issue for a suspected
vulnerability. Include the affected version or commit, a minimal reproduction
and the impact you expect.

## Trust boundaries

- **Driver link:** UDP to the OpenVR driver is loopback-only by default and has
  no authentication. Keep `driver.udp_host` at `127.0.0.1`; exposing it to a
  network lets anyone inject poses, inputs or haptics.
- **Phone link:** IMU, clock-sync and video traffic is plaintext UDP/WebSocket
  on the LAN. Setting `phone.token` authenticates IMU and clock packets with a
  16-byte SHA-256 trailer and protects the video WebSocket with the same token.
  It does not encrypt the stream and it is not a substitute for a trusted
  network.
- **Parsing:** UDP packets are untrusted input. Malformed or truncated packets
  are rejected as `ProtocolError`; the receivers apply a per-source rate limit
  so a flood cannot starve the application.
- **Model downloads:** MediaPipe Tasks models are fetched over HTTPS and
  verified against a pinned SHA-256 and size before they are used. A corrupt or
  interrupted file is never published to the cache.
- **Installer:** the portable installer only modifies the SteamVR `drivers`
  folder and the user's OpenXR/Monado configuration, backs up replaced files
  and records every change so it can be undone.

## Scope

The project does not run a server, collect telemetry or upload camera frames.
Test recordings generated by the emulator E2E use synthetic scenes. A
vulnerability in SteamVR, Monado, MediaPipe, OpenCV or the Android platform
should be reported to the respective project.
